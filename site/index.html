The Cost Of Not Guessing

There is no clock on the table, so nothing has to be fast. Where a street can be counted, the engine counts it — every outcome, not a sample of them — and the answer comes back exact. The bill arrives in seconds.

  1. 01 The river 990 dealer hands All five board cards are known, so the only unknown is the dealer's two. Every one of the 990 possible holdings is graded and counted. The answer is a tally, not an estimate. 9 ms
  2. 02 The flop 1,070,190 outcomes Three board cards known. That leaves 1,081 turn-and-river runouts, each one graded against all 990 dealer hands — 1,081 × 990, every pair, exactly once. The spec suggested sampling here. There is no timer, so there is no reason to. ~9 s
  3. 03 Pre-flop 169 hand classes Nothing to enumerate: the exact count runs to about 100 million runouts per holding, against 1,326 holdings. So it is measured instead — 2,000,000 runouts and 6,000 boards for each of the 169 classes, once, offline. Afterwards a decision costs nothing at all: it is a dictionary lookup. ≈4 h · paid once

The faster wrong answer

There is a way to write the flop enumeration that runs in 2.7 seconds, where the exact one takes about nine. It hands the dealer the two lowest cards of every draw and the board the two highest, and it visits a sixth of the outcome space. Nothing about it looked broken. It reported a 55% push rate on a hand whose true rate is 14%, and it was caught only by cross-checking against an independent Monte Carlo run — which is now a permanent test, so it stays caught.
